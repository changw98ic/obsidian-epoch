# 人生故事报告规则

一局结束时交给玩家的是一整世经历的故事报告，不是事件报告、任务清单、审计日志或模型临时编造的总结。事实来自服务端事件与身份状态，叙事模型负责组织因果、节奏和语言，但不能新增未发生的人物、理由、冲突、物品或结论。

## 固定输出结构

```text
代号：X
轮回第 N 世
身份：……
该局目标：……

故事内容
你现在已经转生成为……
（完整人生故事）

结算影响
（获得或失去的金钱、道具、关系、身份传说度、轮回代号传说度，以及对其他玩家可继承的世界变化）

评价
任务完成度：C / B / A / S（对应及格 / 良好 / 完美 / 惊世，未及格则明确失败）
身份还原度：40%
警告：该身份将无法保留
```

警告文本按实际结算生成；身份无法保留时使用上述明确句式。评价必须是报告最后一节。

## 完整故事的最低构成

故事必须具备起因、发展、转折、结果和余波，并让玩家能回答：

- 时间：使用 [[世界时间与历法]] 的游戏内日期、季节、昼夜和人生阶段，不使用本局运行的现实时间。
- 地点：人物如何从住所、工作地、任务区域和旅途之间移动，不能瞬移。
- 人物：身份本人及实际相遇的重要 NPC；姓名、关系、目标与生死必须来自已保存记录。
- 事件：具体做了什么、为什么当时会这样做、遇到什么阻碍、选择付出什么代价。
- 结果：目标是否解决、人物和世界变成什么样、人生为何结束或该世为何在此结算。

报告覆盖这一世值得讲述的全部阶段，包括基本生存、工作/学习、关系、个人追求、主支线、重大失败与结局。不能只写最后一次任务，也不能把一分钟行动夸写成几十年人生。

## 故事正文禁区

- 正文只讲人物经历，不插入“任务节点已解锁”“完成度 +10%”“服务端判定”等系统话术。
- 不复述同一事实，例如“你带着记录返程，记录也随你被带回来”。
- 不用抽象的“影响”“差值”或系统术语代替具体人物、行为与因果。
- 不为数据缺口编造地点、NPC、实验样本、敌人、动机或失败理由。
- 不要求角色在每次完成任务时把物品带走；所有权、交接、奖励和遗留位置按事件写。
- 不把内部事实记录、JSON、动作日志或评价字段混入故事段落。

## 事实装配与生成流程

1. 服务端冻结结算点，读取身份、时间线、地点、关系、任务、库存、经济、伤病、传说与世界影响。
2. 将事件按游戏时间排序，建立因果边、人生阶段和未解决线索；缺少因果只能写成未知，不能补造。
3. 选出完整人生所需场景，保留重要日常与转折，压缩无变化的重复劳动。
4. 叙事模型生成正文；质量检查器验证结构、时间地点人物、事实覆盖、重复、系统话术和结局。
5. 若正文不合格，使用同一事实包重新生成，而不是给玩家解释“记录不足所以只能这样”。
6. 服务端附加真实奖励、持续世界影响和最终评价；客户端模型无权修改。

## 评价规则

任务完成度读取 [[任务机会与服务端裁定规则]]。身份还原度根据已知身份性格、能力、关系、职责、需求、人生追求和实际行为计算；它衡量“这一世像不像这个人”，不衡量玩家是否服从任务。

身份传说度归属于本世身份；轮回代号传说度只有在代号被世界识别并正确归因时变化。金钱、道具与关系逐项列出来源、去向和是否可继承，对其他玩家的影响只列已提交到连续世界的状态。
