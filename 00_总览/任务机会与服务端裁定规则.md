# 任务机会与服务端裁定规则

任务是世界中的人、组织或公共系统为真实问题提出的合作、委托、试炼、调查或冲突方案。任务内容可以由模型协助推理生成，但可用事实、资源、完成条件、奖励和结果只能由服务端建立并裁定。

## 生成顺序

1. 世界发现机会：短缺、事故、研究需求、岗位、犯罪、战争、贸易、生态、关系或个人目标达到触发条件。
2. 选择任务类型和具体场景地图；场景必须有区域 ID、真实设施、人口、库存、危险和可达路线。
3. 服务端构造 `MissionContract`：发布者、受益者、公开目标、期限、约束、可见评分、预算、奖励来源、失败后果和初始分支。
4. 服务端生成并密封一项与当前世界状态相关的隐藏目标及判定表达式，客户端模型不可读取。
5. 模型基于身份和已知信息提出一条合理路线，可包含调查、交涉、劳动、学习、实验、贸易、战斗或撤退。
6. 每个行动先经服务端校验与执行，事件回写后再由模型叙述；模型不能自行宣布成功、奖励或世界改变。

## 任务类型不是固定线路

类型只约束问题形状，不提供固定脚本。基础类型至少包括：

- 工作与生产：应聘、修理、建造、采收、运输、照护、经营。
- 学习与试炼：入门考核、课程实践、职业认证、宗门/组织试炼。
- 研究与实验：样本、设备、方法、受试者、记录、复现和安全。
- 生存与狩猎：真实食物、威胁、材料或生态管理需求下的追踪与处置。
- 调查与司法：取证、失踪、欺诈、污染、身份、记忆和权属争议。
- 贸易与外交：订单、路线、谈判、制裁、结盟、停战和公共听证。
- 救援与灾害：火灾、洪水、塌方、真空、疫病、腐化和难民安置。
- 阵营与战争：加入、保持中立、渗透、倒戈、调停、后勤和战后治理。
- 关系与人生：家庭承诺、恋爱、师徒、仇恨、赎罪、事业和迁徙。

同一类型在不同地图必须读取当地规则。例如协助实验会因设备、体系、法律和研究目标不同而产生不同路线；城外猎兽必须先存在兽群、威胁、许可、生态和买家。

## 主线与分支图

主线保存为有条件的机会图，而不是三条预写路线。节点可以处于隐藏、可用、受阻、完成、失败或失效状态；边由世界谓词控制。

支线完成本身不解锁主线。只有它产生的证据、关系、许可证、库存、技能、设施状态、公共支持或敌对状态满足边条件时才解锁。新的世界事件也能增加、关闭或替换主分支。

阵营选择必须改变资源来源、盟友、法律权限、敌对关系、可见信息和结局，不能只替换对话文本。保持中立也是有成本和条件的路线。

## 四档完成度

| 档位 | 全局定义 |
| --- | --- |
| 及格 | 公开核心目标达到最低阈值，结果真实且未触发合同中的否决条件 |
| 良好 | 达到及格，并在时间、成本、伤亡、合法性、质量、生态或相关方利益中的多数指标优于最低线 |
| 优秀 | 达到良好，处理至少一个根因和关键支线影响，结果经持续性模拟或复验仍成立 |
| 惊世 | 达到优秀，并且服务端隐藏目标被真实事件证据满足；没有隐藏目标成功就绝不能判惊世 |

评分由任务创建时冻结的规则版本和服务端事件计算。客户端叙述、自称、提示词或单个 NPC 的评价不能改变档位。

## 隐藏目标

隐藏目标不是随机刁难，而是当前问题中未被公开目标覆盖的高价值结果。它必须：

- 可由世界状态推导，存在至少一条可实现但不保证容易发现的路径。
- 不依赖玩家无法获知的纯口令，不要求模型猜服务端文本。
- 有布尔/阈值判定、所需事件证据、失效条件和规则版本。
- 创建后加密或隔离保存，任务结束前不发给客户端模型。
- 结算时只按真实事件验证，不能因故事写得精彩而补判。

## 奖励与失败

奖励可以是 `coin`、物品、aether、工资、职业资历、组织权限、关系、住房/服务权、合法战利品、身份传说度或世界级后续机会。每项奖励有发布者、托管来源、数量、所有权与交付方式。

失败不强制结束人生。可能产生欠薪、伤病、诉讼、关系变化、资源损失、任务转化、救援线或阵营重组。放弃、拒绝和重新谈判也是合法行动，代价由合同与世界状态决定。

## 日志与玩家故事分离

服务端内部保留行动意图、裁定、事件、谓词和评分证据，供审计与 agent 交互；玩家结算读取 [[人生故事报告规则]]，不得直接展示事件 JSON 或逐条日志拼接。
