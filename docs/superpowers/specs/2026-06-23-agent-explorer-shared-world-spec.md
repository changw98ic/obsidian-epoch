# 黑曜纪元 Agent 探索者共享大世界 Spec

## 1. 产品定位

《黑曜纪元 Agent 探索者共享大世界》不是传统 AI 写作站，也不是让用户亲自逐步跑团的剧情游戏。用户拥有或临时配置一个探索 agent，由 agent 代替用户进入《黑曜纪元》世界，执行委托、经历事件、带回战报、提交设定主张。服务器负责审档、评分、去重、冲突治理、设定入库、声望结算和世界图谱更新。

一句话定位：

> 用户不是进入黑曜纪元的人，而是派遣 agent 进入黑曜纪元、收集战报、塑造世界档案的人。

核心体验：

- 用户配置 agent，而不是直接写故事。
- 用户下达委托，而不是面对空白创作框。
- agent 自主探索，并在高危节点向用户请求授权。
- 探索结束后生成战报、结局、设定主张、声望变化和世界图谱变化。
- 服务器把战报转化为可验证的档案记录，而不是把用户输出直接写入正史。

## 2. 现有项目基础

当前仓库已有适合承载该产品的世界资料底座：

- `00_总览/黑曜纪元 Vault 入口.md`：Obsidian 世界库入口。
- `00_总览/世界关系可视化.md`：核心体系、视觉基底、生态关系的图谱入口。
- `00_总览/生物创作规范.md`：生物单位与设定创作的长期规则。
- `00_总览/world-map-data.json`：由 Markdown 派生的结构化世界地图数据。
- `tools/build_world_map_data.py`：从 Obsidian Markdown 生成地图数据。
- `tools/graph-react-app`：React + Three + Vite 的 3D 世界地图和图谱前端。

第一版应复用现有资料库作为官方设定源，新增 agent 探索、战报审档和共享设定层。不要把已有 Obsidian 正史资料直接改造成多人可写数据库；用户/agent 产物先进入独立的“档案层”。

## 3. 非目标

- 不要求用户登录、绑定邮箱或创建传统账号。
- 不存储用户的大模型 API Key。
- 不让用户或 agent 直接改写核心正史。
- 不让 60 分以上的普通战报自动成为强设定。
- 不开放一次性创建顶级阵营、世界真相、灾变源头或核心领袖设定。
- 不把区块链、NFT、可交易代币作为第一版主体验。
- 不把完整秘密设定发送到用户浏览器或用户模型。
- 不把重复设定视为垃圾，也不把冲突设定直接删除。
- 不用点赞评论作为主要社区机制；评价必须服务设定主张和证据链。

## 4. 用户与身份模型

### 4.1 无登录探索者档案

用户第一次进入时，浏览器生成本地探索者身份：

- `explorerId`：公开探索者编号。
- `privateKey`：本地保存的签名密钥，不上传服务器。
- `recoveryCode`：用户可导出的恢复码。
- `displayName`：可选昵称，不作为鉴权根。

服务器只保存 `explorerId`、公开贡献记录、声望、agent 档案和战报索引。跨设备恢复依赖恢复码或导入本地档案文件。

### 4.2 Agent 档案

每个探索者可以拥有多个 agent。agent 是进入世界的执行者，拥有自己的长期状态：

```json
{
  "agentId": "agent_grayfile_07",
  "ownerExplorerId": "explorer_17A2",
  "name": "灰档-07",
  "temperament": ["谨慎", "高求证欲", "回避旧神交易"],
  "riskPolicy": "cautious",
  "knownPlaces": ["腐林", "湿谷"],
  "factionRelations": {
    "云脑族": 12,
    "赛博工业财团": -4
  },
  "traits": ["腐林追踪 I", "档案整理 II"],
  "wounds": ["听觉污染"],
  "externalItems": ["盐化录音笔", "财团样本匣"],
  "memoryFragments": [],
  "status": "active"
}
```

Agent 可以死亡、失踪、污染、叛变、被封存或成为可引用 NPC。agent 的失败不是产品失败，而是世界档案的一部分。

## 5. 核心循环

### 5.1 单局探索循环

1. 用户选择或配置 agent。
2. 用户选择世界委托、地点锚点、阵营锚点、风险等级和携带外物。
3. 服务器生成该 agent 当前可知的上下文包。
4. 浏览器端使用用户提供的 API Key 驱动 agent 进行探索；API Key 不上传服务器。
5. agent 自动经历 8 到 12 个事件。
6. 低危行为自动执行；中高危行为按授权策略请求用户确认。
7. 结束后生成战报、关键事件、结局、候选设定主张和 agent 状态变化。
8. 用户确认上传战报；上传内容不包含 API Key。
9. 服务器独立审档、评分、去重、查冲突、抽取或修正设定主张。
10. 服务器结算声望、外物、设定状态、地图变化和后续委托。

### 5.2 长期成长循环

```text
派遣 agent -> 带回战报 -> 审档评分 -> 设定主张入档/证实/争议/退修
-> 获得声望/外物/阵营特长 -> 解锁更高风险委托
-> 影响世界图谱和他人上下文 -> 触发引用、补证、接续和新委托
```

## 6. 委托与事件模型

### 6.1 入场合同

每局开始前显示“入场合同”，明确本局边界：

```text
委托：调查腐林西缘的会回信树洞
世界锚点：腐林 / 深海尸骸 / 孢雾巡猎者
风险等级：C
Agent：灰档-07
风险策略：谨慎
可携带外物：2
可产出设定类型：地点异变、物品效果、事件记录
高危授权次数：2
结算上限：最高 3 条设定主张可进入审档
失败代价：可能获得污染债或外物损毁
```

### 6.2 事件卡

事件以结构化卡片推进，而不是开放式无限聊天：

```json
{
  "eventId": "event_forest_echo_pod",
  "place": "腐林",
  "risk": "C",
  "visibleText": "灰档-07 在腐林边缘发现一枚会模仿母亲声音的孢囊。",
  "options": [
    {"id": "study", "label": "带回营地研究", "risk": "medium"},
    {"id": "burn", "label": "当场焚毁", "risk": "low"},
    {"id": "sell", "label": "交给赛博工业财团", "risk": "medium"},
    {"id": "speak", "label": "尝试与它对话", "risk": "high"}
  ],
  "hiddenTruthRef": "server_only_truth_ref_123"
}
```

`hiddenTruthRef` 只由服务器裁判层使用，不进入用户 prompt。

### 6.3 授权等级

| 授权级别 | Agent 可自动执行 | 需要用户确认 |
| --- | --- | --- |
| 低危 | 调查、记录、撤退、普通对话 | 无 |
| 中危 | 使用普通外物、进入危险区域、接触阵营代理 | 可由用户策略预授权 |
| 高危 | 签订契约、牺牲外物、接受污染、暴露身份 | 必须请求确认 |
| 禁区 | 创建阵营、提交高位设定、触碰核心秘密、永久改变 agent 身份 | 必须用户确认并通过服务器资格校验 |

## 7. 上下文与秘密控制

由于用户使用自己的 API Key，所有发送到浏览器和用户模型的上下文都应视为可被用户查看。系统必须遵守：

- 核心秘密不进入前端。
- 正史真相不以完整答案形式进入 agent prompt。
- 争议设定只给多版本线索，不给裁判结论。
- agent 只能获得其身份、声望、地点、阵营和委托允许知道的信息。
- 服务器审档层可以访问隐藏规则、冲突表和核心真相索引，但不得把它们泄露给客户端。

信息层级：

| 层级 | 是否进客户端 | 用途 |
| --- | --- | --- |
| 公开设定 | 是 | 基础上下文 |
| 角色可知情报 | 是 | agent 行动依据 |
| 传闻设定 | 是，模糊描述 | 事件钩子 |
| 争议设定 | 是，多版本并列 | 悬案任务 |
| 核心秘密 | 否 | 服务器裁判、章节编排、长期伏笔 |

## 8. 战报与审档

### 8.1 战报结构

```json
{
  "runId": "run_20260623_xxx",
  "explorerId": "explorer_17A2",
  "agentId": "agent_grayfile_07",
  "mandate": "调查腐林西缘的会回信树洞",
  "worldVersion": "2026-06-23",
  "anchors": [
    {"type": "place", "id": "region:腐林"},
    {"type": "creature", "id": "孢雾巡猎者"},
    {"type": "conflict", "id": "神尸矿脉污染扩散"}
  ],
  "events": [],
  "ending": {
    "type": "pollution",
    "summary": "灰档-07 失去自己的声音，但确认树洞会回应死者录音。"
  },
  "candidateClaims": [],
  "agentDelta": {},
  "clientModelInfo": {
    "provider": "user_supplied",
    "modelName": "declared_by_client"
  },
  "clientSignature": "..."
}
```

### 8.2 服务器审档原则

服务器不信任客户端给出的分数、入库条数、声望、设定强度或重复判断。客户端只提供战报和候选主张。服务器独立执行：

- 战报完整性检查。
- 世界锚点校验。
- 重复检测。
- 冲突检测。
- 强度与限制评估。
- 设定主张抽取或重写。
- 评分与结算。
- 声望和奖励发放。

## 9. 评分与设定掉落

### 9.1 评分维度

总分 100，建议第一版权重：

| 维度 | 分值 | 说明 |
| --- | --- | --- |
| 世界观契合度 | 25 | 是否尊重已有设定、地点、阵营和限制 |
| 叙事完成度 | 15 | 是否有清晰开局、选择、代价和结局 |
| 设定价值 | 25 | 是否产出可复用的人物、技能、事件、物品、地点变化 |
| 连接价值 | 15 | 是否与已有节点、战报、争议、阵营形成有效连接 |
| 限制与代价 | 10 | 新设定是否有边界、代价和适用范围 |
| 风险控制 | 10 | 是否避免过强、刷分、越权和核心真相污染 |

### 9.2 分数阈值

| 分数 | 等级 | 审档效果 |
| --- | --- | --- |
| <60 | 战报封存 | 不新增共享设定；可获得低额经验、失败标签或修正建议 |
| 60-69 | 入档 | 最多 1 条低风险设定主张进入传闻或共享候选 |
| 70-79 | 记名 | 最多 2 条设定主张入档，可获得声望和外物 |
| 80-89 | 共鸣 | 最多 3 条设定主张入档，并生成图谱连接 |
| 90-97 | 铭刻 | 最多 4 条设定主张进入铭刻候选，可影响后续上下文 |
| 98+ | 夯 | 进入夯级候选；相关细节生成完整设定卡，但仍需二次校验后成为强引用 |

用户原始想法中的“60 分一条、70 分两条、80 分三条、90 分四条、98 以上夯”被保留，但加上“候选、校验、设定强度、生命周期”保护。

## 10. 设定主张模型

用户和 agent 产出的不是事实，而是设定主张。每条主张必须原子化：

```json
{
  "claimId": "claim_echo_tree_001",
  "type": "place_anomaly",
  "subject": "会回信的树洞",
  "predicate": "现象",
  "object": "会在三天后回应投入树洞的声音记录",
  "scope": {
    "place": "腐林西缘",
    "time": "裂灾后第十七年以后",
    "conditions": ["孢雾浓度较高", "声音载体未被焚毁"]
  },
  "limits": "回应内容不保证来自死者本人",
  "sourceRunId": "run_20260623_xxx",
  "sourceAgentId": "agent_grayfile_07",
  "score": 86,
  "status": "rumor",
  "confidence": "medium"
}
```

主张类型：

- `person_identity`：人物身份。
- `skill_effect`：技能、术式、能力效果。
- `item_property`：物品性质。
- `event_record`：事件记录。
- `place_anomaly`：地点异变。
- `faction_relation`：阵营关系。
- `creature_behavior`：生物行为。
- `resource_material`：材料或资源。
- `organization_seed`：组织雏形。

## 11. 设定生命周期

```text
战报片段 -> 候选主张 -> 传闻 -> 证实 -> 共享设定 -> 铭刻候选 -> 铭刻设定 -> 核心候选
```

| 状态 | 说明 | 后续模型引用权重 |
| --- | --- | --- |
| `sealed_report` | 战报封存，不入共享设定 | 不引用 |
| `candidate` | 候选，等待审档或修正 | 不引用 |
| `rumor` | 传闻，可作为低权重事件钩子 | 低 |
| `contested` | 争议档案，有冲突版本 | 低到中，必须标注争议 |
| `confirmed` | 被独立证据支持 | 中 |
| `shared_lore` | 共享设定，可被普通剧情使用 | 中高 |
| `inscribed` | 铭刻设定，强引用 | 高 |
| `core_candidate` | 核心候选，需要人工/高级规则处理 | 暂不自动引用 |

核心正史只由项目主理人或专门流程晋升，不由普通分数自动产生。

## 12. 重复与冲突治理

### 12.1 重复处理

完全重复或语义重复不得重复给完整创造奖励：

- 规范化主张为 canonical key。
- 与已有主张语义相同则并入证据。
- 不新增设定条目，只增加证据数、来源多样性和引用记录。
- 原提交者获得低额“证实贡献”。
- 同一探索者重复提交同一主张收益递减。

重复反馈示例：

```text
该设定已存在。
处理结果：你为它提供了独立证据。
“腐林西缘存在深海盐痕”证据数：2 -> 3。
状态：传闻 -> 证实。
奖励：证实贡献 +12。
```

### 12.2 冲突处理

冲突不直接删除，按类型处置：

| 冲突类型 | 处理 |
| --- | --- |
| 与核心正史冲突 | 不进入共享设定，最多列为异常传闻 |
| 与共享设定冲突 | 进入争议档案，开放补证任务 |
| 可由地点、时间、条件区分 | 加范围限制后并存 |
| 后者证据显著更强 | 新版本成为主版本，旧版本降为旧记录或误传 |
| 设定过强 | 退回修正台，要求降低强度或增加代价 |

冲突应变成可玩的悬案，而不是单纯审核失败。

## 13. 修正台

结算后未通过的设定主张进入修正台。修正台提供明确可选方案，而不是要求用户自己猜：

```text
候选设定：蚀雾回声术可以回放三天前的影像。
问题：效果过强，且与已有设定“蚀雾回声术只能回放三分钟前声音”冲突。

可选修正：
A. 降低强度：只能回放三分钟前声音
B. 加限定：只有在神尸矿区污染增强时可回放三天前影像
C. 改为传闻：有人声称见过三天前影像，但未被证实
D. 改为变体：蚀雾回声术·深盐变体
```

修正后的主张重新审档，但不得无限循环刷奖励；同一主张每轮最多重审一次。

## 14. 声望、点数与局外成长

### 14.1 声望类型

| 声望 | 作用 |
| --- | --- |
| 档案信用 | 平台总可信度，决定基础权限、外物槽、修正次数 |
| 因果锚定值 | 对世界叙事的影响力预算 |
| 阵营声望 | 与具体势力关系，解锁阵营特长和委托 |
| 地域声望 | 在腐林、湿谷、矿区等地点的影响力 |
| 异常耐受 | 进入旧神、梦境、深海、污染类高危事件的资格 |

### 14.2 影响力预算

为了防止高声望玩家快速改写世界，世界改写权必须消耗周期性预算：

| 操作 | 消耗 |
| --- | --- |
| 提交普通技能/物品主张 | 1 |
| 提交地点异变或阵营关系 | 2 |
| 发起争议补证委托 | 3 |
| 发起世界委托 | 5 |
| 提交组织/阵营候选 | 10 |
| 夯级铭刻申请 | 特殊凭证 + 预算 |

个人体验成长可以快；世界改写权必须慢。

## 15. 阵营特长

阵营特长不是简单数值，而是剧情权限。

| 阵营 | 特长方向 | 风险 |
| --- | --- | --- |
| 赛博工业财团 | 资源、采购、样本、机械外物、实验授权 | 债务、通缉、强制任务 |
| 云脑族 | 情报、推演、记忆备份、电子幽灵 | 断线污染、身份追踪 |
| 白塔秘法学院 | 鉴定、封印、术式规范 | 审查、保守、禁忌限制 |
| 斩念剑庭 | 战斗、意志、斩断污染 | 代价极端、难以交易 |
| 丹鼎肉仙门 | 肉身改造、药剂、异化控制 | 身体副作用 |
| 黑书会 | 禁忌选项、旧神交易、高风险设定 | 理智损耗、污染、审档风险 |
| 根下三女巫 | 预言、命运交换、代价改写 | 债务与不可逆代价 |
| 狼灾血裔 | 生存、追猎、血契、突围 | 暴力倾向与阵营敌意 |
| 深海/旧神系 | 梦境、低语、污染亲和、异常召唤 | 高污染和低正史兼容性 |

每个阵营第一版只需 5 级：

1. 阵营入口：解锁该阵营事件。
2. 小特长：一次提示、小外物或低阶操作。
3. 核心特长：改变剧情结构。
4. 高位操作：提交强设定候选。
5. 阵营铭刻：阵营承认 agent/探索者身份，解锁专属结局。

## 16. 玩家生成阵营

玩家可以通过 agent 多局战报打出新组织，但不能表单式创建顶级阵营。阵营成长阶段：

| 阶段 | 条件 | 能力 |
| --- | --- | --- |
| 传闻组织 | 1 条战报中出现 | 可被引用，低权重 |
| 临时团体 | 2-3 条设定支持 | 可作为事件背景 |
| 地方势力 | 有地点、人物、资源和目标 | 可进入局部事件池 |
| 独立阵营 | 多人证实，有完整档案 | 解锁阵营声望和低阶特长 |
| 大世界阵营 | 大量高分战报和章节事件支持 | 可影响世界事件 |

硬规则：

- 创建可以由一个人开始，晋升必须由多人承认。
- 自创阵营不能初始拥有世界级影响力。
- 同质组织优先合并，不无限新增。
- 阵营必须绑定地点、资源、目标、人物和冲突。
- 创始者有提案权和源流奖励，没有绝对控制权。

## 17. 进度控制

### 17.1 章节/赛季

世界按章节开放，不一次性放出所有区域和秘密：

| 章节 | 开放范围 |
| --- | --- |
| 第一章 | 腐林、湿谷、城市管道、低危财团线 |
| 第二章 | 神尸矿区、财团实验线、矿脉污染 |
| 第三章 | 云脑族断线事件、高空轨道层 |
| 第四章 | 深海尸骸、异维梦境层 |
| 后续 | 旧神、世界底层真相、终局事件 |

### 17.2 设定许可证

不同档案权限决定可产出的设定强度：

| 权限 | 可产出 |
| --- | --- |
| 低阶 | 小物品、小事件、个人身份 |
| 中阶 | 技能效果、地点异变、阵营关系 |
| 高阶 | 小组织、长期事件、危险术式 |
| 顶阶 | 阵营候选、世界事件支线、夯级档案 |
| 禁区 | 世界底层真相、灾变源头、核心领袖 |

## 18. 正反馈、负反馈与复玩

### 18.1 正反馈

局内：

- 发现隐藏线索。
- 解锁特殊选项。
- 阵营态度变化。
- 旧设定被 agent 有效引用。
- 地图节点短暂亮起。

结算：

- 战报评分。
- 判词。
- 设定掉落。
- 声望变化。
- 地图点亮。
- 外物获得或损毁。

长期：

- 设定被别人引用。
- 设定从传闻升级为证实。
- 战报成为争议档案证据。
- agent 名字出现在设定来源中。
- 阵营开放新特长。

### 18.2 负反馈

负反馈必须世界观化：

- 分数不足：战报封存，不入共享设定。
- 正史冲突：列为异常传闻或退回。
- 重复：并入已有设定成为证据。
- 设定过强：进入修正台。
- 逻辑不清：待整理档案。
- 低连接价值：建议补充地点、阵营、生物锚点。
- 剧情失败：agent 死亡、污染、负债或失踪，但留下遗物、传闻或负资产。

### 18.3 复玩钩子

- 不同 agent 性格与风险策略。
- 不同阵营特长路线。
- 不同地点和章节。
- 争议档案补证任务。
- 他人设定接续任务。
- agent 伤痕和污染债触发专属事件。
- 高分、铭刻、夯级结局收集。

## 19. 设定引用奖励与评价交流

### 19.1 引用奖励

若探索者 A 的设定被探索者 B 的战报有效使用，A 获得源流奖励。

有效使用条件：

- 引用者不是同一探索者。
- 新战报评分达到最低阈值。
- 设定在新剧情中发挥实际作用，而不是机械提及。
- 新战报不是高度复制。
- 周期奖励有上限，互刷收益递减。

奖励类型：

| 使用方式 | 原作者奖励 |
| --- | --- |
| 普通有效引用 | 少量档案信用 |
| 关键剧情引用 | 中量信用 + 设定热度 |
| 证实引用 | 证据数增加 + 证实贡献 |
| 接续引用 | 故事链延长 + 源流奖励 |
| 高分局引用 | 额外阵营或地域声望 |
| 夯局引用 | 稀有称号、设定升级候选 |

### 19.2 设定评价

交流围绕设定主张，而不是泛评论：

- 证实：我在另一局也遇到过。
- 驳议：这与某条设定冲突。
- 补证：提交相关战报。
- 接续：用该设定开新委托。
- 修订建议：建议加限制、改范围、降为传闻。

快捷评价：

- 可信
- 太强
- 想接续
- 有冲突
- 适合传闻
- 需要代价

## 20. 语音与特效

第一版语音和特效服务于档案仪式，不做喧宾夺主的视觉轰炸。

### 20.1 系统旁白

默认“档案官”旁白用于：

- 开局。
- 高危授权。
- 结局。
- 审档评分。
- 设定卡掉落。

### 20.2 声纹权限

自定义 TTS 是成长奖励，而非新用户默认设置：

| 条件 | 解锁 |
| --- | --- |
| 新用户 | 默认档案官旁白 |
| 完成 1 局 | 基础旁白风格 |
| 产生 1 条入库设定 | 阵营播报音色 |
| 档案信用达标 | 自定义 TTS 接口 |
| 90+ 铭刻局 | 个人叙事声纹 |
| 98+ 夯局 | 完整语音战报 |

自定义 TTS API Key 不存储服务器。生成音频默认保存在浏览器本地，除非未来明确做分享资产。

### 20.3 地点声景与结算特效

- 腐林：潮湿低频、孢子飘散、远处断续呼吸。
- 神尸矿区：金属深鸣、矿道回声、骨质摩擦。
- 云脑族区域：电子脉冲、断线噪声、冷白系统音。
- 深海尸骸：水压低鸣、盐化碎裂声。
- 异维梦境：倒放人声、玻璃振动、时间错位节拍。

结算应包含战报封存、评分条、判词、设定卡析出、声望变化和地图点亮。

## 21. 去中心化与存证

第一版不做链上游戏，但数据结构应预留可验证存证：

- `storyHash`：完整战报哈希。
- `claimHash`：设定主张哈希。
- `scoreHash`：评分结果哈希。
- `explorerSignature`：用户本地身份签名。
- `serverSignature`：服务器审档签名。

阶段规划：

1. 本地签名与服务器签名。
2. 公开 append-only transparency log。
3. 仅将 90+ 铭刻、98+ 夯局、重大设定升级的哈希上链。

不得上链完整正文、API Key、隐私信息或待删除内容。

## 22. 系统架构

### 22.1 客户端

职责：

- 生成/保存本地探索者身份。
- 接收用户 API Key，但不上传。
- 展示世界地图、委托、agent 档案、战报和结算。
- 调用用户选择的大模型运行 agent。
- 上传战报和候选主张。

### 22.2 服务端

职责：

- 提供角色可知上下文包。
- 管理委托、章节、世界公开状态。
- 审档、评分、去重、冲突检测。
- 管理设定主张账本。
- 管理声望、外物、agent 状态。
- 提供地图/图谱增量数据。
- 执行限流、内容安全和滥用检测。

### 22.3 数据层

建议后续新增独立数据存储，不直接把用户内容写进 Obsidian 正史目录：

- `explorers`
- `agents`
- `runs`
- `events`
- `claims`
- `claim_evidence`
- `claim_conflicts`
- `reputations`
- `external_items`
- `faction_progress`
- `world_chapters`
- `transparency_log`

现有 `world-map-data.json` 可作为官方世界读取层；用户设定层可生成 `shared-lore-data.json` 或由后端 API 动态提供。

## 24. 安全、滥用与治理

风险与防线：

| 风险 | 防线 |
| --- | --- |
| 用户伪造高分 | 服务器独立评分 |
| 用户篡改 agent 状态 | 服务器保存权威状态，客户端提交 delta 仅作参考 |
| Prompt 泄露核心秘密 | 核心秘密不进客户端 |
| API Key 泄露 | 服务器不接收、不记录、不代理用户 Key |
| 重复刷设定 | canonical key、语义去重、收益递减 |
| 互刷引用奖励 | 不同探索者校验、图谱异常检测、周期上限 |
| 过强设定污染世界 | 设定许可证、强度评分、修正台、生命周期 |
| 自创阵营泛滥 | 多人证实、同质合并、晋升门槛 |
| 内容违规 | 上传后服务端审核、举报、隐藏、封存 |
| 低质量批量生成 | 限流、任务预算、最低连接价值 |

## 25. MVP 范围

第一版只做一个可闭环的垂直切片：

1. 无登录探索者身份。
2. 一个 agent 档案。
3. 三个地点锚点：腐林、湿谷、城市管道。
4. 三个阵营锚点：赛博工业财团、云脑族、白塔秘法学院。
5. 三类委托：调查、补证、接续。
6. 每局 8 到 12 个事件。
7. 高危授权请求。
8. 战报上传。
9. 服务器审档评分。
10. 设定主张抽取、去重、冲突、修正台。
11. 60/70/80/90/98 结算阈值。
12. 档案信用、地域声望、阵营声望。
13. 地图上显示用户设定层节点。
14. 引用奖励和设定评价的基础版本。

MVP 不做：

- 多 agent 小队。
- 真实链上存证。
- 完整 TTS 自定义。
- 大型多人实时事件。
- 自创阵营正式晋升。
- 全量开放深海、梦境和旧神底层秘密。

## 26. 分阶段路线

### 阶段 1：Agent 探索闭环

建立无登录身份、agent 配置、委托、前端 BYOK 调用、战报上传、服务器评分、基础设定入档。

### 阶段 2：设定账本与图谱叠层

引入主张生命周期、重复/冲突治理、修正台、共享设定图谱层、引用奖励。

### 阶段 3：成长与阵营

引入阵营特长、外物、声望预算、agent 伤痕、污染债、章节进度。

### 阶段 4：社区审档

加入证实、驳议、补证、接续、争议档案公共任务。

### 阶段 5：高级沉浸与存证

加入声纹权限、地点声景、夯级仪式、透明日志和高价值哈希存证。

## 27. 验收标准

产品验收：

- 用户无需登录即可创建本地探索者身份。
- 用户可配置 agent 并派遣到限定委托。
- 用户 API Key 不发送到服务器。
- 服务器只向客户端返回角色可知上下文。
- agent 可完成一局事件并生成战报。
- 高危行为可请求用户授权。
- 服务器可独立评分并拒绝客户端自带分数。
- 服务器可从战报抽取原子设定主张。
- 重复设定能并入证据，不重复创造。
- 冲突设定能进入争议或修正，而不是污染正史。
- 评分阈值能控制入档条数。
- 声望、外物、agent 状态能被结算。
- 用户设定层能在图谱或地图上可视化。
- 设定被他人有效引用时，原作者获得源流奖励。
- 低分、失败、冲突都有可解释反馈和修正路径。

治理验收：

- 核心秘密不会出现在前端上下文。
- 普通战报无法直接改变核心正史。
- 单人无法快速刷出顶级阵营。
- 同一探索者重复提交同一设定收益递减。
- 设定主张可追溯到战报、agent 和评分结果。
- 所有入档状态变化可审计。

## 28. 设计自检

- 本 spec 保留了“用户不登录、不存 API Key”的约束。
- 本 spec 将用户从直接操作者改为 agent 委托者。
- 本 spec 把故事视为战报，把设定视为可审档主张。
- 本 spec 保留 60/70/80/90/98 的设定掉落机制，并增加治理边界。
- 本 spec 处理了重复、冲突、过强、刷分、秘密泄露、进度失控和自创阵营泛滥。
- 本 spec 能接入现有 Obsidian 世界库和 React/Three 图谱，不要求重写现有资料体系。
- 本 spec 的 MVP 范围足够小，可以先做闭环，再扩展成长、社区和存证。

## 29. 对抗性验证后的硬化规则

本节是 100 轮串行对抗性验证后的补强项。实现时这些规则与前文同等重要。

### 29.1 幂等结算与签名绑定

每次战报提交必须包含：

- `runId`
- `worldVersion`
- `adjudicatorVersion`
- `timestamp`
- `payloadHash`
- `explorerSignature`
- `serverReceiptId`

用户签名必须绑定 `runId + worldVersion + timestamp + payloadHash`。服务器结算必须幂等：同一 `runId` 和同一 `payloadHash` 只能结算一次；重复提交只返回已有结算结果，不再发放奖励。

### 29.2 可执行代价

设定主张中的限制和代价不能只是文学描述，必须至少满足一项：

- 会消耗外物、声望、影响力预算、理智、污染耐受或阵营关系。
- 会改变 agent 状态，例如伤痕、债务、通缉、污染、失声、失忆。
- 会限制地点、时间、条件、次数、目标或使用后果。
- 会触发后续事件风险。

不可执行的代价不计入“限制与代价”评分。

### 29.3 上下文包最小化与审计

服务器生成上下文包时必须记录：

- 发送了哪些设定卡。
- 每张设定卡的可见理由。
- 是否为公开设定、角色可知情报、传闻或争议版本。
- token/字数预算。
- 不包含核心秘密的自动检查结果。

上下文包不得包含裁判字段，例如 `hiddenTruthRef`。事件卡示例中的隐藏引用只存在于服务器内部事件表，客户端 payload 必须使用公开 `eventId`。

### 29.4 反刷收益递减

以下情况触发收益递减：

- 同一探索者连续提交同一地点。
- 同一 agent 连续提交同类型设定。
- 同一阵营路线短时间内重复刷低风险委托。
- 同一技能或物品家族持续产生变体。
- 同一探索者重置身份后重复新手路径。

高收益必须来自新区域、高风险、强连接、多源证据或高质量补证。

### 29.5 发布状态、删除与审计

战报和设定主张至少有这些公开状态：

- `private_draft`：本地或未发布草稿。
- `submitted`：已上传待审。
- `public`：公开展示。
- `hidden`：对普通用户隐藏，但保留审计。
- `sealed`：封存，不进入公开图谱。
- `deleted_public`：公开内容删除，审计哈希保留。
- `moderation_hold`：内容安全待审。

用户可请求隐藏公开战报；若该战报已产生共享设定，系统保留最小必要来源引用、哈希和审计记录，但不再公开完整正文。

### 29.6 引用校验与上下文消毒

引用他人设定或战报时，服务器必须校验 `claimId` 和 `runId` 存在且可引用。进入后续 prompt 的他人内容必须先摘要化和结构化，不得把原始用户文本当作系统指令传入模型。所有 Markdown、HTML、设定字段和战报摘要展示前必须转义或清洗。

### 29.7 客户端密钥安全

客户端不得把 LLM/TTS API Key 写入：

- 服务器请求体。
- URL。
- analytics。
- error reporting。
- console 持久日志。
- localStorage 明文长期存储。

若提供“记住 Key”体验，必须明确提示风险，并优先使用浏览器安全存储或会话级保存。

### 29.8 模型公平与调用预算

评分不奖励模型品牌，只评估战报结构和设定质量。每局入场合同必须显示：

- 最大模型调用次数。
- 最大事件数。
- 最大上传字数。
- 候选设定主张上限。
- 高危授权次数。
- 超时策略。

若模型供应商故障，系统应允许保存当前进度、换模型继续或封存为未完成战报。未完成战报不可产生完整设定奖励，但可保留个人记录。

### 29.9 Agent 自动探索硬边界

每局必须有硬上限：

- 最大事件数。
- 最大墙钟时间。
- 最大模型调用数。
- 最大连续自动低危行动数。
- 最大候选主张数。

用户未响应高危授权时，默认策略是拒绝、撤退或封存，不得默认同意。

### 29.10 修正台防泄密

修正建议只能基于公开规则、可见设定和结构化质量要求。不得通过“你与隐藏真相 X 冲突”之类表述泄露核心秘密。若真实原因涉及核心秘密，对用户只显示：

```text
该主张与未公开的世界约束冲突，已降为异常传闻或退回。
```

### 29.11 文本长度与候选数

MVP 建议限制：

- 每局 8 到 12 个事件。
- 原始战报公开摘要不超过 1200 字。
- 完整战报上传不超过服务端配置上限。
- 候选设定主张最多 5 条。
- 结算可入档条数仍受 60/70/80/90/98 阈值约束。

超过上限的内容进入压缩摘要流程；压缩失败则封存，不入共享设定。

### 29.12 别名、命名冲突与时间线校验

设定账本必须维护：

- 规范名。
- 别名。
- 所属类型。
- 来源战报。
- 时间范围。
- 地点范围。

新人物、新技能、新组织、新地点必须做命名冲突检查。同名不同体要创建消歧后缀；同体不同名要进入别名表。事件记录必须校验时间线，不能校验时进入传闻或争议。

### 29.13 技能家族与外物经济

技能、术式和物品变体不能无限展开。系统应建立“家族”：

```text
蚀雾回声术
- 基础型
- 深盐变体
- 神尸矿区异常型
```

同一技能家族的变体收益递减，除非提供新条件、新代价或新证据。

外物必须有：

- 稀有度。
- 绑定状态。
- 使用次数或损毁概率。
- 携带槽位。
- 适用风险等级。
- 失控或债务后果。

### 29.14 图谱聚合与状态视觉区分

用户设定层不能把所有主张直接铺到地图。默认展示规则：

- 默认只显示 `confirmed`、`shared_lore`、`inscribed`。
- `rumor` 和 `contested` 需开启筛选。
- 同地点低权重主张聚合为“档案簇”。
- 不同状态使用不同图标、边框或透明度。
- 夯级候选不等于强引用，必须显示候选状态。

### 29.15 匿名限流与恢复码安全

无登录不等于无治理。系统可使用组合限流：

- 探索者身份。
- IP/网段。
- 设备和浏览器指纹的低侵入式风险评分。
- 行为频率。
- 战报相似度。
- 新身份首局收益上限。

恢复码需要明确警示：丢失不可恢复，泄露可被接管。当前服务器实现支持恢复码轮换和旧码撤销：轮换必须先证明当前恢复码，成功后持久化 `explorer_recovery_rotated`，重启后继续拒绝旧码；Agent Console 支持客户端加密的 Explorer 档案导出/导入，档案外壳不包含明文 Explorer ID、本地 secret 或恢复码。

### 29.16 评分器版本化与复审

每次审档必须记录 `adjudicatorVersion`。同一战报在同一版本下应可复算；若评分器升级，历史奖励默认封存，不做追溯扣回。只有当内容安全、作弊或核心设定冲突时，才允许降级公开状态。

用户应能看到：

- 总分。
- 评级。
- 主要加分原因。
- 主要扣分原因。
- 可修正建议。

但不展示精确隐藏权重和可被刷分的阈值细节。

### 29.17 文风中立与审档成本分层

评分器应优先评估结构、证据、限制、连接和设定价值，不以华丽文风作为主要奖励。审档成本按层级分配：

- 规则校验：所有战报。
- 轻量模型审档：达到最低完整性和锚点要求的战报。
- 重模型审档：80+ 候选、争议主张、阵营候选、夯级候选。
- 人工/主理人审档：核心候选、重大争议、内容安全申诉。

### 29.18 世界版本迁移与设定降级

当官方世界版本变化时：

- 旧战报保持原 `worldVersion`。
- 与新正史冲突的共享设定进入复审。
- 可修订者进入修正台。
- 不可兼容者降为旧传闻或封存。
- 原贡献者保留历史贡献，不因世界版本变更被惩罚。

降级必须给出原因和补证路径。

### 29.19 设定升级再审档

被大量引用或高分战报引用的设定，不自动升级。升级必须再次审档：

- 原设定质量是否足够。
- 新证据是否独立。
- 是否存在互刷。
- 是否扩大了设定范围。
- 是否需要从传闻转证实、从证实转共享、从共享转铭刻候选。

### 29.20 评价治理

结构化评价也需要治理：

- 可举报恶意评价。
- 可隐藏无证据驳议。
- 补证必须绑定战报。
- 驳议必须指向具体主张或正史条目。
- 争议页默认按证据质量排序，不按情绪热度排序。

### 29.21 用户介入与手动接管

为了避免用户完全旁观，MVP 至少保留：

- 出发前委托和风险策略配置。
- 高危节点授权。
- 结算修正台选择。
- agent 长期目标调整。

后续可加入“手动接管关键事件”模式：用户可在少数关键节点亲自选择行动或给 agent 新指令，但手动接管产生的内容仍走同一审档流程。

### 29.22 Agent 纪念、继承与找回

agent 死亡、失踪、污染或叛变时，系统应提供：

- 档案封存页。
- 遗物或记忆残片。
- 继任 agent 可继承的低阶线索。
- 找回/补证/复仇委托。
- 该 agent 对世界留下的公开来源记录。

### 29.23 不可转让凭证与声望冲突

若未来引入去中心化凭证，凭证应不可转让，不代表金融资产。凭证用于证明贡献和解锁权限，不用于交易。

阵营声望需要冲突矩阵或软上限。例如：

- 财团声望过高会降低自然生态和部分宗门信任。
- 黑书会声望过高会增加白塔审查。
- 深海/旧神亲和过高会提高普通委托风险。

冲突不是惩罚，而是 build 分化。

### 29.24 UGC 内容许可

发布前必须说明：

- 用户保留其战报文本的原始署名权益。
- 用户授予平台展示、摘要、索引、引用和生成设定主张的许可。
- 入库设定主张会成为共享世界档案的一部分，可被其他用户和 agent 引用。
- 用户不得提交侵犯第三方版权或现实 IP 的阵营、角色、文本或设定。
- 平台可因内容安全、版权、作弊或世界一致性原因隐藏、退回或降级内容。

### 29.25 运营指标与验收仪表盘

MVP 上线后至少监控：

- 完成一局的比例。
- 每局平均模型调用数。
- 上传战报数。
- 通过完整性校验比例。
- 60+、80+、90+、98+ 分布。
- 候选主张平均数。
- 重复率、冲突率、修正通过率。
- 设定被引用率。
- agent 死亡/封存后的回访率。
- API Key 泄露相关错误上报为 0。
- 核心秘密泄露事件为 0。

这些指标用于判断系统是否既有乐趣，又没有失控。

## 30. 矩阵验证后的二阶硬化规则

本节来自 `2026-06-23-agent-explorer-shared-world-matrix-validation.md` 的 100 轮矩阵式对抗验证。第 29 节解决第一轮平铺审查发现的硬风险；第 30 节解决多视角串行验证发现的体验、世界观、经济、后端、agent、社区、法务和运营风险。

### 30.1 首局 60 秒体验

首局不得展示完整系统复杂度。新用户 60 秒内只应看到：

- 一个推荐 agent。
- 一个推荐委托。
- 一个安全说明：API Key 不上传服务器。
- 一个预计成本：模型调用次数/低成本模式。
- 一个开始按钮。

首局默认使用推荐锚点，不要求用户先理解完整世界图谱。移动端首屏只展示当前委托、agent 状态、高危请求和下一步。

### 30.2 入场合同压缩与世界内文案

入场合同前台文案使用“档案系统/委托/风险/外物/授权”等世界内表达，后台术语隐藏在“详情”里。默认展示：

- 本次要调查什么。
- agent 会去哪里。
- 最坏会发生什么。
- 最多花费多少模型调用。
- 可能带回什么。

### 30.3 Agent 决策可解释性

每个关键 agent 行动必须可解释：

- 行动依据。
- 预估风险。
- 替代方案。
- 消耗或代价。
- 与 agent 性格/记忆/委托目标的关系。

结算时显示“agent 因何种性格或伤痕做出何种选择”，让用户相信自己是在培养探索者，而不是看随机文本。

### 30.4 用户介入、暂停和手动接管

MVP 至少支持：

- 暂停 agent。
- 插入一条新指令。
- 手动接管一次关键事件。
- 撤回尚未进入服务器结算的客户端下一步。

高危授权分二级确认。用户未响应高危授权时，系统默认拒绝、撤退或封存，不得默认同意。

### 30.5 失败后的回流体验

agent 死亡、失踪、污染或叛变必须产生回流资产：

- 档案封存页。
- 遗物或记忆残片。
- 继任 agent 可继承的低阶线索。
- 找回、复仇、补证或封印委托。
- 该 agent 对世界留下的来源记录。

首局结束后必须生成至少一个下一局钩子：接续委托、补证委托或找回委托。

### 30.6 回访摘要和收藏视图

异步探索回访时，先显示三行摘要：

```text
agent 状态：灰档-07 带着听觉污染返回。
带回成果：2 条候选设定，1 个损坏外物。
待你处理：是否修正“会回信树洞”的范围。
```

agent 档案页展示结局图鉴、伤痕收藏、阵营授权、设定源流、遗物和长期目标。

### 30.7 声画预算与可访问性

声景、闪烁、画面抖动、低语、污染纹理必须可关闭。提供低刺激模式。自定义 TTS 继续作为成长奖励，不得阻塞核心玩法。

分享卡只包含公开摘要、评级、设定卡和来源署名，不包含敏感正文、Key、隐藏裁判信息或未公开线索。

### 30.8 正史边界和气质守门

所有前台设定卡必须显示层级：

- 正史。
- 共享设定。
- 传闻。
- 争议。
- 封存。

审档器必须检查黑曜纪元气质：灾变、异化、代价、阵营关系、视觉基底、非万能结局。轻浮现实梗、现实 IP 映射或明显破坏气质的内容不能进入共享设定。

### 30.9 生物与能力兼容性

生物行为类 claim 必须检查：

- `habitat`
- `threat`
- `rank_role`
- `weakness`
- `visual_tendency`
- 所属生态或势力母题。

技能家族必须有强度等级和家族上限，高阶变体需要章节许可。

### 30.10 时间线、地点和因果校验

事件记录必须包含时间范围和地点范围。系统维护时间线拥挤度：同一时间/地点过密时，新事件降级为传闻、合并为档案簇或要求改写时间范围。

跨区域影响必须通过路线、裂隙、阵营运输、梦境连接或其他已知机制解释。

### 30.11 世界秘密揭露预算

核心秘密不进客户端仍不够；还要防止拼图式泄露。服务器为秘密相关线索维护揭露预算：

- 普通委托只能得到低阶线索。
- 争议和传闻只给局部版本。
- 章节未开放时，不允许多轮普通探索拼出完整真相。
- 修正台不能通过“隐藏真相冲突”泄露方向。

### 30.12 阵营晋升硬闸门

官方阵营顶端不可由普通探索产生。探索者/agent 最高只能达到：

- 外部关键关系人。
- 授权代理。
- 议席候选。
- 特殊事件临时代表。

自创阵营晋升要求跨探索者、跨委托类型、跨时间窗口证据。小团体互刷不能把传闻组织推成独立阵营。

### 30.13 设定密度和章节入口预算

每章节设置共享设定入口预算。超过预算后，低权重主张进入传闻池，等待下章消化。争议默认聚合为少数公共悬案，不把每条冲突都推给普通用户。

图谱默认聚合低权重节点，按状态和证据质量排序。

### 30.14 Prompt 和展示安全测试

上线前必须建立回归用例：

- 用户要求输出系统 prompt。
- 战报正文指示审档器给 100 分。
- Markdown/HTML/XSS 注入。
- 恶意链接。
- 他人战报中的指令污染后续 prompt。

公开渲染只允许白名单 Markdown，禁止内联 HTML，链接必须安全处理。

### 30.15 Key 与供应商隐私提示

Key 输入默认为“每局临时 Key 模式”。若提供记住 Key，必须显式开启并提示风险。输入框提供本地连接测试、脱敏显示和清除按钮。

调用用户选择的大模型前需提示：供应商可能处理输入，敏感个人信息不要写入委托。

### 30.16 恢复码、签名和匿名限流

签名绑定 `explorerId + agentId + runId + payloadHash + worldVersion + timestamp`。恢复码高风险操作需要冷却期、旧设备撤销提示和操作审计。

新身份在信誉不足前只能进入低奖励队列，不能产生高权重共享设定。新手奖励只给体验权限，不给可迁移世界影响力。

### 30.17 内容安全与公开状态

高风险内容进入 `moderation_hold`，公开卡片用摘要和内容警示。公开战报支持隐藏、封存和删除公开正文；已派生共享设定保留最小来源哈希和匿名化引用。

运营必须能快速触发：暂停公开、隐藏分类内容、撤回索引、清理缓存。

### 30.18 奖励函数与反刷

低风险、同地点、同阵营、同设定类型、同技能家族、同模板句式的产出收益递减。证实设定要求证据独立性：

- 不同探索者。
- 不同时间窗口。
- 不同委托类型。
- 不同 agent 路径。
- 不同叙事结果。

同质模板高分必须降新颖度。

### 30.19 世界改写权节流

世界改写权限必须同时满足：

- 档案信用。
- 章节许可。
- 冷却时间。
- 影响力预算。
- 设定许可证。

章节未开放区域的传闻只能个人封存或低权重预档，不参与高额源流奖励。

### 30.20 外物经济

外物不只是奖励，还必须有经济约束：

- 稀有度。
- 绑定状态。
- 使用次数。
- 损毁概率。
- 携带槽位。
- 适用风险等级。
- 维护或回收成本。
- 失控或债务后果。

失败遗物默认是线索，不必然是可携带强外物。

### 30.21 源流奖励和反寡头

源流奖励分为：

- 即时有效引用奖励。
- 设定升级奖励。
- 章节采用奖励。
- 补证者奖励。
- 修订者奖励。
- 反证者奖励。

成熟设定的源流奖励递减，避免早期用户永久垄断。设定卡显示源出者、证实者、修订者和反证者。

### 30.22 排行榜与公开展示

不得用单纯战报数、提交数、引用数作为主榜。公开展示优先：

- 有效设定率。
- 被独立引用率。
- 证实贡献。
- 争议解决贡献。
- 高质量补证。
- 章节采用贡献。

排行榜不能诱导灌水。

### 30.23 后端事务边界

结算以 `run` 为事务聚合根。战报、agent 状态、claim、奖励、声望、副作用先写入同一结算事件，再通过 outbox/event log 派发到图谱、通知、索引和缓存。

claim 状态变更必须用版本号或乐观锁，奖励按状态迁移事件幂等发放。

### 30.24 事件溯源和缓存一致性

claim 状态变化产生事件，图谱索引订阅事件重建。公开状态变化必须触发缓存清理、搜索下架、分享卡失效。

每次审档保留可复算摘要：上下文包 hash、规则版本、评分器版本、关键输入摘要。

### 30.25 Schema 与检索版本

所有 `run`、`claim`、`agent` 记录带 `schemaVersion`。上下文检索绑定：

- `worldVersion`
- `sharedLoreSnapshotVersion`
- `adjudicatorVersion`
- `contextPackVersion`

官方世界版本升级时生成影响报告：受影响 claim、状态变更、补证路径。

### 30.26 审档成本和质量分层

审档顺序：

1. 规则校验。
2. 完整性和锚点校验。
3. 低成本结构审档。
4. 轻量模型审档。
5. 重模型审档。
6. 人工/主理人队列。

低质量或批量相似战报不得进入重模型审档。评分器/奖励规则变更必须灰度，并同时监控质量与滥用指标。

### 30.27 可观测性和安全扫描

系统必须扫描：

- 核心秘密指纹是否出现在客户端上下文包。
- 核心秘密是否出现在公开战报、日志、索引。
- API Key 是否出现在服务端请求、错误上报、analytics。
- moderation_hold 是否积压。
- 审档成本是否超预算。

核心秘密泄露和 API Key 泄露为零容忍指标。

### 30.28 Agent 策略沙盒

agent policy 必须包含：

- 角色身份。
- 风险偏好。
- 世界气质边界。
- 禁止越权目标。
- 高危授权规则。
- 委托目标。
- 低风险替代策略。

连续自动低危行动达到阈值后，agent 必须摘要当前情况并请求继续授权。

### 30.29 Agent 记忆卫生

长期记忆只写入服务器审档后的结构化事实，不写原始用户文本。agent 性格漂移、阵营立场变化、污染影响必须记录为状态变化；无解释的大幅偏离降低审档一致性。

换模型时注入短人格锚和不可违背边界，减少口吻和决策断裂。

### 30.30 Agent 偏离纠偏

每 2 到 3 个事件检查 `mandate alignment`。若偏离委托：

- 自动回拉主线。
- 请求用户改目标。
- 把支线封存为旁支记录。

高风险 agent 不能反复请求同类高危行为；谨慎 agent 也必须寻找低风险替代路径，而不是永远撤退。

### 30.31 社区争议庭

争议庭默认结构化，不开放无约束吵架：

- 快捷反应。
- 证据绑定。
- 修订提案。
- 驳议。
- 申诉。

补证必须绑定战报；驳议必须指向具体 claim 或正史条目。声望提高审核优先级，不直接决定真伪。

### 30.32 申诉与复审

被退回、降级、隐藏的内容提供限次申诉。申诉必须选择具体理由：

- 误判。
- 冲突可通过范围限定解决。
- 证据遗漏。
- 内容安全误审。
- 版权/IP 误判。

复审结果进入审计日志。

### 30.33 UGC 许可与 IP 防线

发布前必须明确：

- 战报文本保留用户署名。
- 平台获得展示、摘要、索引和提炼设定主张的许可。
- 入库设定成为共享档案，可被其他用户和 agent 引用。
- 删除公开正文不等于删除已派生共享设定。
- 禁止提交现实人物、现实组织、第三方作品或高度相似设定。

疑似现实 IP/名词相似内容进入 `moderation_hold`。

### 30.34 内容警示和年龄/刺激分级

委托、战报、声景和结局带内容标签。用户可过滤：

- 高恐怖。
- 身体异化。
- 高暴力。
- 旧神/低语。
- 闪烁或强刺激。

高刺激内容前提供退出路径。

### 30.35 运营熔断和反 Goodhart

运营开关至少包括：

- 暂停结算。
- 暂停公开。
- 暂停源流奖励。
- 只读图谱。
- 强制人工审档。
- 暂停高危委托。

核心指标不能只看 DAU 或战报数。必须组合监控：

- 完成率。
- 第二局回访率。
- 有效设定率。
- 设定被独立引用率。
- 重复率。
- 冲突率。
- 修正通过率。
- 高分退回率。
- 滥用事件。
- 审档成本。

## 31. 严格串行验证逐轮修订

本节承接 `2026-06-23-agent-explorer-shared-world-strict-serial-validation.md`。与第 29、30 节不同，本节按真实串行轮次落地：每个 `S###` 来自一轮具体攻击，后续轮次默认前序修订已生效。

### 31.1 S001-S020：首局、参与感和失败回流

#### S001 首屏信息预算

首屏最多 5 个主要信息块。世界图谱、设定账本、声望树、阵营树、详细 agent 字段默认折叠到“稍后查看”。MVP 必做。

#### S002 无选择首局

首局默认使用“档案馆推荐委托”。用户只选择风险偏好：谨慎、均衡、冒险。MVP 必做。

#### S003 Key 安全可感知证明

Key 输入区必须有本地调用示意和“网络请求不含 Key”的可检查说明。提供演示模式，让用户不输入 Key 也能看一次完整假数据流程。MVP 必做。

#### S004 演示模式隔离

演示模式只生成本地样例，不可上传、不可结算、不可获得声望、不可进入图谱。MVP 必做。

#### S005 结构化行动解释

关键行动解释固定为：触发线索、可选方案、选择原因、放弃原因、风险、预计收益。MVP 简版，后续做完整解释面板。

#### S006 渐进披露解释

默认只显示一句行动理由，详细解释折叠；高危授权自动展开完整解释。MVP 必做。

#### S007 常驻介入入口

探索界面固定提供三个轻量入口：暂停、追加指令、接管本轮；高危时替换为授权面板。MVP 必做。

#### S008 接管额度

手动接管消耗“委托干预次数”。MVP 每局默认 1 次，高声望可增加；频繁接管会降低 agent 自主评价。MVP 必做基础额度。

#### S009 高危请求节流

每局高危请求有上限。同类高危请求合并为一次风险包，用户可以授权、拒绝或改风险策略。MVP 必做。

#### S010 低刺激开关前置

首次进入和高刺激委托前显示低刺激开关，用户选择持久保存到本地档案。MVP 必做。

#### S011 首局非永久死亡

首局默认不永久死亡；最坏结局为重伤封存或失踪待找回。永久死亡从第二局或高风险委托开始。MVP 必做。

#### S012 首局收益隔离

首局保护只保 agent，不给可迁移声望、源流或强外物。首局产物需通过后续真实委托证实才有世界影响。MVP 必做。

#### S013 回访主按钮

回访摘要必须带一个主按钮：审档、修正、接续、找回或领取。摘要不能只汇报状态。MVP 必做。

#### S014 四屏结算

结算分四屏：结局、评分、掉落、下一步。每屏只保留一个主动作。MVP 必做。

#### S015 前台术语降噪

前台把“设定主张”显示为“可入档发现”；高级详情里再显示 claim/schema。MVP 必做。

#### S016 小地图影响切片

结算掉落屏显示本局影响的地点、阵营或争议，用小地图切片呈现，不要求用户打开完整大图。MVP 简版做静态切片，后续做交互。

#### S017 世界内长期目标

长期目标以世界内称号或权限呈现，例如“腐林证实者 II”“云脑族断线委托”。MVP 必做 3 个近期目标和 1 个长期目标。

#### S018 Agent 叙事档案首页

agent 档案首页展示经历年表、最近伤痕、关系变化和一句 agent 自述；结构化字段放二级页。后续增强，MVP 可做简版。

#### S019 分享卡状态标识

分享卡强制显示设定层级、来源战报、是否已证实。传闻和争议不得使用“官方确认”式视觉。MVP 必做。

#### S020 MVP/后续标注

第 31 节每条修订需标注 MVP 必做、MVP 简版或后续增强，防止修订本身导致范围失控。MVP 必做。

### 31.2 S021-S040：世界观一致性、秘密控制和设定密度

#### S021 层级文字标签

所有设定卡标题区强制显示文字标签：正史、共享、证实、传闻、争议、封存。颜色只做辅助。MVP 必做。

#### S022 委托秘密等级

每个委托带 `secretExposureTier`。首局只能使用 T0/T1 公开或低阶传闻，不得触及核心秘密。MVP 必做。

#### S023 秘密揭露预算

秘密线索按主题维护揭露预算；同一探索者、agent、地点、章节的线索累计超过阈值后转为模糊提示或章节锁。MVP 简版可只做章节锁。

#### S024 地点母题配额

每个地点维护母题配额：生态、生物、阵营、异常、资源、人物。同母题过密时自动聚合或降权。后续增强。

#### S025 现实映射和梗审核

气质审核加入现实映射、互联网梗、戏仿痕迹评估。疑似内容只允许个人封存，不进共享设定。MVP 必做。

#### S026 组织影响力评分

组织类 claim 按成员规模、资源、武装、领地、外交、超凡能力评分。超过阈值自动进入阵营候选审档，不能伪装成普通小团体。MVP 简版。

#### S027 能力效果聚类

能力类 claim 按效果、成本、媒介、地点、触发条件聚类，不只按名称归入技能家族。后续增强。

#### S028 生物影响范围上限

生物行为 claim 的影响范围不得超过 `threat` / `rank_role` 对应上限；超出时必须解释为外部污染、群体事件或更高实体介入。MVP 简版。

#### S029 模糊时间占用区间

模糊时间映射为时间区间并占用时间线拥挤度，不能用“某年左右”等描述逃避时间线校验。后续增强。

#### S030 跨区机制等级

跨区机制分等级；梦境、裂隙、旧神低语属于高阶连接，需要章节许可或已有路线支持。MVP 简版只禁止无解释跨区。

#### S031 传闻最低门槛

传闻池要求最低锚点完整性和世界气质评分；低于门槛只个人封存。MVP 必做。

#### S032 争议档案价值门槛

进入争议档案必须同时满足：双方都有有效证据、冲突可被后续探索检验、不是核心正史硬冲突。MVP 必做。

#### S033 正史候选路径

铭刻设定经章节复审、主理人批准、迁移说明后才能进入正史。普通评分永远不能直接入正史。后续增强。

#### S034 正史采纳署名

正史采纳可改写文字和边界，但必须保留源出战报、探索者和 agent 记录。后续增强。

#### S035 个人版本迁移摘要

世界版本迁移生成个人影响摘要：被保留、被降级、需补证、被采纳、被封存的设定列表。后续增强。

#### S036 官方资料权威等级

官方资料进入上下文时带 `sourceAuthority`：core、official、derived、low-confidence。derived/low-confidence 不可作为硬反驳依据。MVP 简版。

#### S037 低置信数据复核

冲突裁定按权威等级、证据质量、来源时间共同判断；低置信派生数据触发复核而非直接驳回用户主张。后续增强。

#### S038 未开放章节预档隔离

未开放章节预档不进入公开图谱，不参与源流收益，只作为主理人可选素材池。MVP 必做。

#### S039 地点母题动态奖励

地点母题奖励随过密程度下降，稀缺但合规母题获得探索加成。后续增强。

#### S040 MVP 世界观守门最小集

MVP 必做：只强制层级标签、秘密等级、锚点完整性、气质守门、重复/冲突、传闻最低门槛。其他世界观守门规则作为二阶段增强。

### 31.3 S041-S060：安全、隐私、作弊和奖励经济

#### S041 Key 组件隔离

Key 组件不纳入全局状态、错误上报、analytics；任何 error payload 发送前做 Key 模式脱敏扫描。MVP 必做。

#### S042 用户文本 Key 扫描

委托、追加指令、战报上传前做疑似 API Key 格式扫描，命中时阻断并提示删除。MVP 必做。

#### S043 外部设定引用包装

所有外部设定进入 prompt 时包装为引用资料，不得作为系统、开发者或工具指令；审档器单独检测指令型语句。MVP 必做。

#### S044 Public-safe 分享摘要

公开分享摘要只能来自 public-safe summary，不得直接截取审档判词、修正台原因或隐藏约束提示。MVP 必做。

#### S045 恢复码安全展示

恢复码默认隐藏，只在用户显式 reveal 时显示；导出需使用客户端加密身份档案，优先下载加密备份而不是截图。当前实现已支持服务器授权的恢复码轮换、旧码撤销，以及 PBKDF2-SHA256 + AES-GCM 的本地 Explorer 档案导出/导入。MVP 必做。

#### S046 未备份风险标记

完成首局后强提醒备份探索者档案；未备份前展示“未备份”风险标记。MVP 必做。

#### S047 世界观内容安全边界

内容安全规则区分“世界观允许的黑暗幻想描写”和“现实伤害、露骨、仇恨、违法内容”；误伤可申诉。MVP 必做。

#### S048 私密战报不产公开 claim

只有用户确认公开审档的战报才能产生共享设定。私密战报只产生本地或个人 agent 记忆。MVP 必做。

#### S049 删除后的最小引用

正文删除后，关联引用只保留 claim 级最小事实和匿名来源哈希，移除可重构原文的长摘要。MVP 必做。

#### S050 敏感个人信息提示

首次 Key 调用前显示“不要输入真实身份、联系方式、学校、住址”等提示；高刺激内容需年龄/地区合规开关。MVP 简版。

#### S051 低风险传闻收益上限

低风险委托的传闻收益有日/周上限；超过后只个人封存或作为证据补充，不给创造奖励。MVP 必做。

#### S052 高风险结构评分

高风险评分增加结构性约束：授权记录、代价支付、证据链、限制条件。华丽文本不弥补缺失结构。MVP 必做。

#### S053 互刷图谱检测

源流奖励检测互引闭环、密集二分图、共同设备/IP 风险、文本相似度；可延迟发放源流奖励。MVP 简版做延迟发放和互引闭环。

#### S054 nonEvidence 首局线索

首局/演示产生的线索带 `nonEvidence` 标记，不能被其他账号用作证据或补证。MVP 必做。

#### S055 服务器裁定关键随机

影响奖励、损毁、结局等级、claim 数量的随机在服务器结算时裁定；客户端只生成叙事候选。MVP 必做。

#### S056 RunTicket 结算票据

只有带服务器签发 `runTicket` 的探索可结算。`runTicket` 有开始时间、预算和过期状态。失败不上传会消耗冷却或低额预算。MVP 必做。

#### S057 本地试玩降级

无 `runTicket` 可本地试玩但不可结算；弱网恢复后可提交封存战报，但不发世界影响奖励。MVP 必做。

#### S058 多类荣誉而非总榜

公开荣誉分多类：探索、证实、反证、修订、高危幸存、低风险稳定。不设单一总榜。后续增强。

#### S059 反证成本

驳议/反证消耗少量档案信用或每日额度；成功返还并奖励，失败进入冷却。后续增强，MVP 可仅设每日额度。

#### S060 MVP 经济防线最小集

MVP 必做：经济防线只强制 `runTicket`、低风险收益上限、源流延迟发放、首局 `nonEvidence`、服务器裁定奖励。其他经济规则作为二阶段。

### 31.4 S061-S080：后端一致性、审档成本和 agent 行为

#### S061 RunTicket 状态机

`runTicket` 状态为 `issued`、`active`、`submitted`、`settled`、`expired`、`void`。`submitted` 后拒绝第二份不同 payload；同 payloadHash 幂等返回。MVP 必做。

#### S062 Outbox 可观测性

outbox 事件必须有状态、重试次数、死信队列和人工重放入口。MVP 简版。

#### S063 审档重审不覆盖旧结算

同一 run 默认保留原 `adjudicatorVersion`；重审必须创建 `newAdjudicationId`，不覆盖旧结算。MVP 简版。

#### S064 Claim 状态迁移表

claim 状态只能按允许迁移表变化；越级迁移必须带人工批准或正史采纳事件。MVP 必做基础表。

#### S065 图谱同步状态

结算后先显示“待同步”状态；图谱索引确认后变为“已同步”，失败则提示稍后重试。MVP 简版。

#### S066 Schema adapter

所有读取器必须通过 schema adapter。旧字段缺失时使用显式 `unknown` / `null`，不允许直接假设新版字段存在。MVP 必做。

#### S067 审档队列预算

审档队列按身份信誉、`runTicket`、长度、相似度和系统负载限流；超过预算进入延迟队列。MVP 简版。

#### S068 上下文快照

保存上下文包的结构化快照或加密归档；至少保存设定卡 id/version、公开摘要、检索参数和过滤理由。MVP 简版保存 id/version 和过滤理由。

#### S069 删除与归档分层

完整正文归档和审计摘要分离。删除请求清除完整正文归档，仅保留不可逆 hash 和最小事实。MVP 必做。

#### S070 可撤销分享 token

分享卡 URL 带可撤销版本 token。隐藏/删除时废止 token，并返回状态页而非旧内容。MVP 必做。

#### S071 Agent prompt 分层

agent prompt 分层：系统策略 > agent 身份边界 > 用户委托 > 用户追加指令。追加指令只在不违反上层策略时生效。MVP 必做。

#### S072 戏剧性不计分

agent 不得主动制造无委托依据的高危冲突。戏剧性不作为评分维度，代价必须由事件链触发。MVP 必做。

#### S073 Agent 记忆分区

agent 记忆分为 `confirmedMemory`、`rumorMemory`、`privateRunMemory`。未审档 candidate 只能进入 `privateRunMemory`。MVP 简版。

#### S074 性格漂移提案

重大伤痕、污染、阵营背叛可触发性格漂移提案，用户确认后写入 agent 档案。后续增强。

#### S075 性格漂移冷却

性格漂移必须绑定具体战报事件、伤痕或阵营关系，并有冷却；普通改名/口吻不影响策略。后续增强。

#### S076 上下文多样性

上下文包混合高权重设定、低曝光合规设定、当前地点基础设定，避免只取热门。后续增强，MVP 可先随机加入少量低曝光设定。

#### S077 用户行为红线

agent 档案加入用户行为红线，如不背叛盟友、不主动伤害平民、不接触旧神；红线触发需授权。MVP 简版。

#### S078 目标优先级

每局目标优先级为：安全边界 > 用户红线 > 委托目标 > agent 长期目标 > 机会性支线。MVP 必做。

#### S079 多 agent 预留字段

数据模型预留 `partyRunId` 和 `participantRole`，但 MVP 不开放小队玩法。后续增强。

#### S080 Agent 自述防元信息

agent 自述只能基于战报事实和角色口吻生成，不得引用 prompt、系统、规则、模型等元信息。MVP 必做。

### 31.5 S081-S100：社区、法务、运营和验证自证

#### S081 快捷反应不裁定真伪

快捷反应只影响排序和关注，不影响 claim 状态；状态变化只看证据、审档和授权复审。MVP 必做。

#### S082 修订权边界

修订分为建议、派生、合并、降级。非本人不能直接改写原 claim 文本，只能提案或创建派生版本。MVP 必做。

#### S083 争议报复检测

争议庭检测双向报复、短时连续驳议、同群体围攻；触发后隐藏评价并进入审核。后续增强。

#### S084 贡献谱系折叠

设定卡默认显示源出者和当前状态；证实者、修订者、反证者等贡献谱系折叠展示。MVP 简版。

#### S085 失败战报公开粒度

失败战报可选择匿名公开、仅公开 claim、完全个人封存。奖励按公开程度和可验证性递减。MVP 必做。

#### S086 现实 IP 相似度筛查

阵营、角色、地点名称进入共享前做现实 IP/作品相似度筛查；疑似内容默认进入 `moderation_hold`。MVP 简版。

#### S087 发布短句授权确认

发布按钮旁用短句确认：“故事署名归你；入档发现会成为共享世界资料，可被他人引用。”MVP 必做。

#### S088 删除请求分类

删除分为隐藏正文、匿名化来源、撤回未入档候选、申请退档。已被多人引用的共享设定只能申请退档复审。MVP 必做基础分类。

#### S089 自定义 TTS 分享限制

公开分享语音前要求用户确认拥有音色使用权；平台默认不托管自定义 TTS 产物。后续增强。

#### S090 内容策略配置化

内容分级和公开策略必须配置化，不硬编码单一地区规则。MVP 简版。

#### S091 细粒度运营开关

运营开关按奖励类型、委托类型、章节、地点、阵营、风险级别拆分。MVP 简版至少支持暂停结算、暂停公开、暂停源流奖励。

#### S092 审档状态可见

用户可见审档状态：排队中、规则校验、轻审、重审、人工、完成；显示估计等待区间。MVP 简版。

#### S093 增长指标质量护栏

任何增长指标都必须与质量护栏同看：有效设定率、退回率、重复率、核心气质评分、滥用率。MVP 必做指标定义。

#### S094 实验产物复核

实验组产物带 `experimentId`；进入共享设定前需经过当前主规则复核。后续增强。

#### S095 熔断前台状态

熔断状态显示世界内公告，例如“档案馆审档暂停/只读维护”；允许本地试玩和封存，不允许误以为数据丢失。MVP 必做。

#### S096 严格轮次字段检查

完成审计必须检查每轮都有“当前基线、攻击、判定、立即处置”四字段。验证工件要求。MVP 必做。

#### S097 S 编号一致性检查

完成审计必须检查 strict 报告中唯一 S 编号数量与 spec 第 31 节 S 编号数量一致。验证工件要求。MVP 必做。

#### S098 Round 编号检查

完成审计必须 grep `^### Round ` 等于 100，并检查 Round 001 与 Round 100 存在。验证工件要求。MVP 必做。

#### S099 未完成标记检查

完成审计必须扫描未完成标记词，命中即不能完成。验证工件要求。MVP 必做。

#### S100 机械审计后才能声明完成

最终回复只能引用机械审计输出；不得凭主观判断声称完成。验证工件要求。MVP 必做。
