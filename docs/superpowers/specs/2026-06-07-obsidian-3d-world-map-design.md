# 黑曜纪元 3D 多层世界地图设计

## 目标

将现有“星图 / 知识图谱”升级为《黑曜纪元》的 3D 多层世界地图。地图不再以节点宇宙为主视觉，而以世界空间为底座：高空低轨、地表城市与森林、地下矿区、深海尸骸、梦境层、非三维空间等层级共同构成世界本体。生态、势力和冲突事件作为可切换叠加图层显示在同一套空间结构上。

第一版目标是让用户直观看到“这个生物、势力或污染源位于世界哪一层、影响哪些区域、与哪些生态或势力发生关系”，并保留现有右侧档案面板、图片资产和 Obsidian 数据来源。

## 非目标

- 不做真实地球 GIS，不绑定经纬度、WGS84、OpenStreetMap 或在线地图瓦片。
- 不把 Cesium、deck.gl、iTowns、MapLibre 作为第一版主底座。
- 不追求完整游戏地图编辑器；第一版是可浏览、可聚焦、可扩展的世界观沙盘。
- 不在第一版解决所有空白地点页和旧版生物骨架条目的设定缺口，但地图要能标识这些条目为“待扩写”。

## GitHub 调研结论

- [supershaneski/react-three-terrain](https://github.com/supershaneski/react-three-terrain)：适合参考 height map 生成 3D 地形的方式，轻量，MIT。可借思路，不需要直接迁移项目。
- [RodrigoHamuy/react-three-map](https://github.com/RodrigoHamuy/react-three-map)：适合真实 MapLibre/Mapbox 地图中嵌入 Three/R3F 对象。它证明“地图坐标 + 3D 对象 + 可点击标记”可行，但对黑曜纪元这种虚构世界不是最佳底座。
- [tentone/geo-three](https://github.com/tentone/geo-three)：适合参考地图瓦片、LOD 和自定义 tile provider 思路；真实地理依赖较强，第一版不直接使用。
- [CesiumJS](https://github.com/CesiumGS/cesium)、[deck.gl](https://github.com/visgl/deck.gl)、[iTowns](https://github.com/iTowns/itowns)：能力强，但偏真实 GIS 和大规模地理数据。对当前虚构多层世界过重。

推荐技术路线：继续使用现有 `tools/graph-react-app` 的 React + Three + Vite 工程，替换星图布局为自定义多层沙盘。第一版不新增重型 GIS 依赖；若需要更声明式的 Three 组件，再评估是否加入 React Three Fiber。

## 世界空间模型

地图本体由固定层级组成，每层是一个可显示、隐藏、半透明叠加或单独聚焦的 3D 地形板块。

| 层级 | 作用 | 示例节点 |
| --- | --- | --- |
| 高空层 | 低轨残骸、星外坠落、轨道污染 | 高空低轨、星霜小蛇、裂隙尘蛹 |
| 地表城市层 | 城市管网、赛博工业、贫民窟污染 | 城市管道、工业废液、线缝鼠、霓尘蛾 |
| 地表生态层 | 腐林、湿谷、山海森林、野外异化生态 | 腐林、湿谷、山海森林、孢雾巡猎者 |
| 地下矿区层 | 废弃矿区、神尸矿脉、采掘污染 | 废弃矿区、神尸矿区、矿泪小蜥 |
| 深海层 | 深海尸骸、盐化、旧神低语 | 深海尸骸、盐尸鲸、膜鳃小螺 |
| 异维层 | 梦境、非三维空间、星外裂隙 | 非三维空间、时间鳞蛇、星胎虫 |

每层使用独立高度、颜色、雾效和边界。层之间通过“裂隙 / 管道 / 矿脉 / 梦境渗漏 / 星外坠落”连接，而不是用普通图谱边线漂浮在空中。

## 叠加图层

地图在同一个世界底座上切换不同读法。

### 生态模式

显示生态区、栖息地、生物分布、污染扩散与资源采集点。适合回答：

- 某个生物出现在哪一层、哪些地点。
- 哪些低级生物提示附近有更高等级污染源。
- 哪些生态区共享基底气质或弱点。

### 势力模式

显示势力控制、渗透、封锁、采掘和饲养/制造关系。适合回答：

- 哪些势力控制某一层或某个区域。
- 某个势力低级生物为什么会出现在这里。
- 财团、宗门、审判庭、女巫环等势力如何跨层行动。

### 冲突事件模式

显示跨层污染、剧情路径、冲突轴、危险前兆和事件触发点。适合回答：

- 神尸矿区如何污染腐林、湿谷或工业区。
- 星外裂隙如何影响高空、梦境和地表生态。
- 玩家沿一条剧情路径会依次经过哪些层和节点。

## 数据模型

新增导出数据文件建议命名为 `00_总览/world-map-data.json`。它从 Markdown 条目派生，不替代 Obsidian 双链。

核心结构：

```json
{
  "layers": [
    {
      "id": "surface_ecology",
      "label": "地表生态层",
      "height": 0,
      "regions": ["腐林", "湿谷", "山海森林"]
    }
  ],
  "regions": [
    {
      "id": "腐林",
      "layer": "surface_ecology",
      "shape": "blob",
      "position": [80, 0, 40],
      "radius": 42,
      "terrain": "fungal_forest"
    }
  ],
  "entities": [
    {
      "id": "孢雾巡猎者",
      "type": "creature",
      "layer": "surface_ecology",
      "region": "腐林",
      "position": [90, 8, 48],
      "overlayRoles": ["ecology", "conflict"],
      "sourcePath": "04_异化生物/孢雾巡猎者.md"
    }
  ],
  "routes": [
    {
      "id": "神尸矿脉污染扩散",
      "mode": "conflict",
      "points": ["神尸矿区", "废弃矿区", "腐林", "湿谷"]
    }
  ]
}
```

### 数据派生规则

- `04_异化生物` 的 `habitat` 优先决定生物落点。
- 没有 `habitat` 的旧版生物使用 `ecology`、`source_section` 和正文第一句推断层级，并标记为低置信度。
- `03_势力组织` 的势力生物通过 `faction` 字段或“所属势力”正文关系落点。
- `05_地点生态` 是区域节点；占位页仍可显示，但视觉上标记为“待扩写”。
- `08_关系网络` 转换为冲突事件模式下的路线、边界或影响带。
- 现有图片资产继续用于实体图标和右侧详情面板。

## 视觉与交互

- 主视图是倾斜 3D 沙盘，不再是球形或星云空间。
- 左侧面板控制世界层级显隐、叠加模式和过滤条件。
- 顶部搜索保留，可搜索生物、地点、势力和事件。
- 右侧详情面板保留现有档案结构：摘要、图片、外观、能力、弱点、关系、路径。
- 点击区域聚焦到该层；点击生物或势力标记打开详情。
- 世界层级可三种状态切换：单层、半透明叠层、全部展开。
- 生态模式使用地貌颜色和污染雾；势力模式使用疆域边界和控制色；冲突事件模式使用路径、裂隙、扩散带和高亮前兆。

## 技术设计

### 第一版实现路径

1. 新增 `tools/build_world_map_data.py`，从 Markdown 和现有图谱数据生成 `world-map-data.json`。
2. 在 `tools/graph-react-app` 中新增地图视图组件，替代或并列现有 `GraphScene`。
3. 使用 Three.js 自定义 mesh 构建层级地形、区域块、标记、路径和雾效。
4. 复用现有数据加载、搜索、详情面板、图片预览和 Vite 构建流程。
5. 新增导出入口 `00_总览/黑曜纪元3D世界地图.html`，旧星图可保留为历史入口或跳转到新地图。

### 地形生成

第一版不需要真实 height map 文件。每个区域使用参数化地形：

- 腐林 / 湿谷：低洼起伏、雾绿材质、半透明孢雾。
- 神尸矿区 / 废弃矿区：断裂台地、矿脉沟壑、锈黑与暗金线。
- 深海尸骸：深蓝黑平面、骨白尸骸轮廓、盐化粒子。
- 城市管道 / 工业废液：管网线、工业格栅、废液池。
- 非三维空间：错位半透明板块、裂隙线和异常旋转标记。
- 高空低轨：漂浮残骸环、冷白星霜粒子。

后续如果需要更复杂地形，再引入 height map 生成器或参考 `react-three-terrain` 的像素高度读取方式。

## 验证标准

- 运行 `npm run build` 能生成静态站点和 `world-map-data.json`。
- 新 HTML 在本地浏览器中能打开，首屏显示非空 3D 多层地图。
- 可以切换生态、势力、冲突事件模式。
- 可以切换世界层级的单层、叠层、展开状态。
- 点击至少 1 个地点、1 个生物、1 个势力、1 条事件路径时，右侧面板显示正确来源资料。
- `孢雾巡猎者`、`线缝鼠`、`符芯傀犬`、`盐尸鲸`四类代表样本都能落到合理层级。
- 移动端不出现文字重叠；主要按钮和面板可点击。

## 风险与边界

- 现有很多地点生态页仍是占位，地图初版需要用推断和默认区域补齐；这些节点应明确显示低置信度。
- 旧版 25 个生物缺少完整 `habitat`、`weakness`、`threat` 字段，地图落点会比图像设定草案弱。
- 如果第一版过早接入 Cesium/deck.gl/MapLibre，会把虚构世界问题变成真实 GIS 问题，增加坐标、瓦片、投影和外部服务负担。
- 如果未来需要多人编辑地图坐标，应把 `world-map-data.json` 的手工坐标抽成独立配置，避免每次从 Markdown 重新推断覆盖人工调整。

## 分阶段范围

### 第一阶段：可用沙盘

构建多层地图底座、三种叠加模式、基础交互、详情面板和代表节点落点。

### 第二阶段：设定补全

扩写地点生态节点和旧版生物骨架，提升自动落点和路径置信度。

### 第三阶段：地图编辑能力

允许手工调整区域形状、实体坐标和冲突路径，并把调整写回配置文件。

## 自检

- 本 spec 没有把世界分层误写成第三种平级视图；世界分层是地图本体。
- 生态、势力、冲突事件是叠加图层。
- 第一版避免重型 GIS 依赖，符合虚构世界和现有工程约束。
- 没有未决的 TBD/TODO；不确定项以风险和阶段边界记录。
